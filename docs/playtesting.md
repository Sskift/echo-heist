# 试玩记录与十小时验收

当前版本包含 C0–C6 和 C7 前三个任务，不能进行完整八章时长验收。本协议和工具是准备工作，仓库中没有外部玩家的实测数据。单元测试中的合成记录、浏览器测试导出、参考路线和 750 分钟预算都不是真人证据。

## 参与与记录

先冻结待测版本。完整主线发布门槛要求至少 20 份符合条件的首次完成记录，包含经常玩和较少玩潜入解谜的外部玩家。保留全部开测者的名单、未完成记录和退出原因；不能只留下用时较长的完成者。招募、首次游玩身份和实际观察需要负责人在工具之外核实。

每位测试者使用自己的全新浏览器配置或独立本机账号，从 C0-1 开始。不要删除个人正在使用的游戏存档，也不要共用同一份试玩记录。测试者没看过关卡答案或参考输入；开发者熟悉路线后的体验不能算首次盲测。

1. 打开「试玩记录（仅本机）」，选择真实的试玩身份、解谜经验和是否使用外部攻略，再开始记录。默认身份是开发 / 调试，避免把开发操作误计为外部首次试玩。
2. 正常使用游戏内提示、暂停、预演、重录和快进。没有为了测试而禁用的标准辅助功能。卡住、失败、理解过程都需要记录。
3. 离开时点「离开一会儿」，回来后点「已回来」，再主动继续游戏。失焦和后台时间不计有效用时。超过两秒的无法解释计时空洞标为 unclassified，由人工核对，工具不自动补入。
4. 分次游玩可刷新或关闭后继续。关闭页面的间隔不会计时。更新版本会标记为混合版本，不能直接并入同一版本的发布统计。
5. 结束或退出时停止记录、导出 JSON。文件由玩家自行交给测试负责人，游戏不上传、不发送消息。负责人保存原文件与观察记录，不修改原始导出以“修正”时长。

记录包含匿名会话 ID、版本、身份类别、各行动区的墙钟时间、提示层数事件、开始、重试、保存、失败和成功。分支使用同一行动区编号累计用时与完成状态，checkpoint 事件记录实际布局及提交选择；替代布局不重复计入必经体量。不会录制屏幕、麦克风、账号或完整键盘文本。停止后不再追加试玩事件；本机存储失败时仍可直接导出当前内存数据。

计时以 performance.now 的实际经过时间为依据。把十二秒模拟快进三倍，只会记录实际花费的四秒；自动脚本跳过模拟等待也不会生成对应的人类思考时长。自动化浏览器导出被标为 automation，审查直接排除。

## 人工复核

按每章观察记录分辨：有意义的规划、执行和合理试错，与挂机、强制等待、机械返工、刷取或重复已完成任务。后者必须从有效时间扣除。自动采集不能独立判断这些区别；文件哈希也不能证明测试者是真人。

每章结束后请玩家用自己的话说明：

- 本章的关键配合是什么，和上一章相比哪里不同？
- 最困惑或反复失败的地方在哪里，是否能解释原因？
- 当前拿到的证据说明了什么，为什么要去下一个地点？

完整结局后核对玩家是否理解搭档的去向、记忆交易、回声技术边界和最终选择的后果。八章观察笔记必须逐章填写；不能用八次复制的“好玩”代替体验审查。另保留每章时长、提示、失败、退出位置和原因的分析，检查是否有章节靠重复挫败拖长流程。

人工复核单与原始导出放在同一个专用目录。用原始文件的完整字节计算 SHA-256；PowerShell 示例：

```powershell
(Get-FileHash -Algorithm SHA256 -LiteralPath '.local/playtests/participant.json').Hash.ToLowerInvariant()
```

复核单结构如下。以下是字段示例，不能直接作为已完成的验收材料：

```json
{
  "kind": "echo-heist-playtest-review",
  "sessionId": "填入原始导出的匿名ID",
  "dataSha256": "填入原始文件的64位SHA256",
  "reviewer": "实际复核人",
  "reviewedAt": "实际复核时间的ISO格式",
  "firstPlayConfirmed": false,
  "guideUseChecked": false,
  "excludedMs": 0,
  "reason": "逐项说明扣除的挂机、返工等时段；没有扣除也需说明核对依据",
  "outcome": "complete",
  "storyUnderstood": false,
  "noveltyNotes": ["C0观察", "C1观察", "C2观察", "C3观察", "C4观察", "C5观察", "C6观察", "C7观察"]
}
```

未完成者使用 outcome: withdrew，仍保存导出和复核单，并在 reason 中记录退出位置和原因。不要谎填通关状态或补造缺失的行动区。

同一目录另需一份全体开测名单：

```json
{
  "kind": "echo-heist-playtest-cohort",
  "build": "实际冻结版本",
  "sessionIds": ["全部开测者的匿名ID，包括退出者"],
  "recruitmentNotes": "实际招募方式、人数与首次接触核验依据；私下保存同意记录与匿名ID的对应",
  "reviewer": "实际负责人",
  "externalFirstPlayConfirmed": false
}
```

只在已核实后填写确认字段。试玩文件包含行为数据，默认保留在被 Git 忽略的 .local 下，不推送个人原始记录。

## 运行审查

```sh
npm run audit:playtime -- .local/playtests
```

命令使用主线预算目录列出的全部 132 个必经行动区，检查实际运行时内容是否齐全。即使导出虚构了后续完成 ID，缺少章节时也不能通过。

工具检查版本、首次身份、自动化标识、外部攻略、全部必经区、人工复核、原始文件哈希、完整开测名单、重复或缺失文件，以及完整剧情和八章体验笔记。计算时剔除非主线、离开和未分类时间，再扣除人工确认的无效时段。退出者单独报告，不用其卡关时间拉高通关时长。

验收目标：至少 20 份合格首次完成记录，覆盖两类经验玩家；有效主线时长中位数 720–840 分钟，第 25 百分位不少于 600 分钟。输出 passed: false 和退出码 1 表示未达标或材料不齐，退出码 2 表示调用目录缺失。CI 不用不存在的真人数据假装通过此门槛。

工具通过只说明提交材料内部符合条件。招募真实性、材料完整性、人工扣除与剧情评价仍要核实。最终发布结论需结合原始记录、每章分布、所有退出者和观察笔记。时长不足时补充有独立解题点的必经内容，再组织新版本首次盲测，不能靠延长计时器或补填数据达标。
