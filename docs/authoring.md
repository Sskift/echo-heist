# 行动区制作与验证

任务总目录在 `src/campaign-content.ts`，C1–C5 内容分别在 `src/chapter-one.ts`、`src/chapter-two.ts`、`src/chapter-three.ts`、`src/chapter-four.ts`、`src/chapter-five.ts`，共用制作函数在 `src/campaign-authoring.ts`；模拟只依赖 `Level`。后续章节各用独立文件导出任务，再接入总目录。新增任务应先写清独立解题点、剧情作用和失败反馈，再摆放设施。

## 内容结构

`Mission` 包含稳定 ID、章节、名称、任务说明、完成证据和有序的 `Stage[]`。每个阶段包含：

- `level`：地形、实体、出生点、目标、出口、规则提示。
- `story` / `result`：行动前通讯与成功后的新事实。
- `requires` / `grants`：上一阶段必须提交的事实与这一段产生的事实。
- `witness`：可执行的参考输入，确保这段确实能完成。
- `alternatives`：不同原理的替代输入；校验器逐条实际回放。章末和 C6 开放任务需要多解，不能只将同一路线平移几个坐标。

任务流程只继承已提交的事实。切换行动区创建新的 `Game`，重新安排回声；不继承任意守卫位置或录制草稿。

`room()` 使用 30 × 18 的 32 像素网格。竖墙格式是 `[列, 开口行数组]`，横墙格式是 `[行, 开口列数组]`，最后一个参数是单块障碍的坐标。设施和角色使用像素坐标；须给半径 10 的角色留足间距。

`Level.objective` 为 `reach` 时，只需抵达 `exit`；否则取走 `loot` 后抵达 `exit`，未提供出口时使用出生点。每段仍固定 12 秒、最多三个回声。

## 设施

- 门可以同时要求开关、`power`、时间窗口和 `authorization`，存在的条件必须全部满足。
- 单开关用 `plate`；多开关用 `plates` 加 `plateMode`：`all`（默认）、`any`、`one`（恰好一个）或 `none`（全部松开）。
- `Plate.window` 是开关响应时间；`Door.window` 是单个门禁窗口，`Door.windows` 是多个可通行窗口。多个窗口之间为“或”，与其他条件之间为“且”。时间单位为秒，起点包含、终点不包含。
- `scanners` 定义矩形区域、`period` 周期秒数、`active` 活跃区间、可选 `phase` 偏移和 `power`。连续暴露 18 帧失败；出场前或抑制期间的回声不参与扫描。短暂安全不保证整个 12 秒都安全，参考解需要在下一轮危险到来前完成目标。
- 电源设施定义 ID 与初始布尔状态。录制存储“设为接通/断开”的意图，避免回放盲目翻转状态。
- `Circuit.label` 说明面板用途，`states: [false状态名, true状态名]` 为分流器命名两种去向；仍是同一布尔状态，不产生额外电源。界面显示门、摄像头与照明连接，出口不要求所有门同时打开。
- 摄像头用 `kind: 'camera'`，保持朝向、不移动、不调查声音，`power` 决定是否感知。守卫的 `lighting: {id, on, darkRange}` 在对应照明未供电时缩短视距；听觉不变，`darkRange` 必须大于零且不大于正常视距。显示与感知使用同一个 `visionRange`。
- `lootPower`、`exitPower` 是必须全部成立的电路状态数组，分别约束真人取物与完成撤离。`onLoot: {power, message}` 定义只触发一次的取物后变化与预告文字；必须有实体藏品与可读预告。操作请求先结算，真人拾取后再应用变化并更新门，之后才判断撤离。新安保状态从下一帧进入感知。预演、回声、重录都不会触发实体取物；重试恢复地图初态。
- 凭据终端分为 `source`、`relay`、`lock`。每区最多一份唯一凭据；锁的授权名可供门和后续终端引用。只有持有人可以交付或授权，授权后仍持有凭据。交付、接收、授权依次结算，同帧多人接收会取消请求。
- `Terminal.window` 在起点帧开放、终点帧关闭，约束交付、接收、授权；`power`、`plate`、`requiresAuthorization` 分别要求供电、远端留守与已有签名，条件全部成立才操作。电源按本帧最新请求，开关按与门相同的占用采样；地图、交接面板公开条件。
- `waitForDelivery: true` 仅用于非锁终端：按 E 登记接收，站在 30 像素范围内等到终端开放且凭据送达。离开、被抑制或新的操作会取消；成功或竞争冲突后清除请求。终点待命可保留已登记请求，不会重复发出意图。普通终端仍只处理按键那一帧，空手请求可在后来轮次得到不同结果。
- 留候是每轮临时状态，不写入计划；存档保存原来的 take/give/authorize 意图，重试与预演从这些动作重建。预演不含真人，依赖真人送件的路线可能显示接收失败，这不是存档丢失。第二棒要先实际拿到凭据才能录下 give；不能凭空录出持有物。
- 抑制场可以常开、受 `power` 控制或使用 `cycle: {period, active, phase?}` 定义公开周期；供电与周期条件同时成立才生效。周期以固定帧计算，起点包含、终点不包含。重叠场只要任一生效就抑制回声，真人始终不受影响。
- 失效回声沿原记录继续移动、保留唯一凭据，但不压开关、不操作终端或电源、不发声，也不被安保看见。恢复不补放错过的操作，已取消的留候需要新的接收请求。不能把抑制写成暂停录像或销毁凭据。
- `glass` 是带 ID 的矩形障碍，挡住真人与守卫，不遮视线；墙与玻璃都不隔声。墙在 `Game` 创建时建立空间索引，运行期间不修改墙数组；门始终按实时状态判断。
- 守卫 `facing` 可显式定义初始弧度朝向，缺省时由路线前两个点计算。单点岗位返回后恢复 `facing`。固定哨兵 `kind: 'sentry'` 不移动、不响应噪声。
- `hearing` 是听觉半径，缺省 450 像素；`searchSeconds` 指定抵达声源后的搜索秒数，行程不消耗搜索时间，随后绕障碍返回岗位。未指定时保留旧地图从听见起倒计时 2.5 秒的行为。
- `kind: 'tracker'` 只识别可见回声，忽略真人；同帧按距离、稳定回声 ID 选择目标。看见时保存位置，失去视线后追向最后位置，`traceSeconds` 到期返回原路线（缺省 1.5 秒，必须在 0–12 秒内）。墙遮视线，玻璃不遮；抑制回声不会更新线索。
- 追踪器需要明确的 `searchSeconds`。声响调查覆盖视觉追踪，抵达后搜索；调查期间仍可能看见回声并触发暴露。断电同时清除追踪、声响调查与警觉。线索属于单轮临时状态，重试、重录、预演都从录制动作重建，不能写入计划存档。
- `noiseResponse: 'nearest'` 将同帧声源批量配对：先排除固定哨兵、未供电和听不到的守卫，再按距离、守卫稳定 ID、声源 x/y 排序，每个声源与守卫最多分配一次。相同位置的同帧声音合并。此模式要求守卫 ID 唯一且稳定；缺省 `all` 保留范围内全员响应。
- `soundMarkers` 仅提供 N1 等地图参照名，声音仍可在任意位置发出。它不参与碰撞或调度，不应被写成必须精确踩中的机关。C2 从作者参考输入提取响点，提示用这些名称与方位说明安排。

所有设施 ID 使用字母、数字、下划线和短横线，最多 32 字符。修改已经发布的地图布局或规则时，要使用新的行动区 ID 或明确提供迁移，避免旧录像静默套到新地图。

`Level.hints` 可提供递进提示，第一层指出观察对象，第二层解释关系，第三层才说明具体安排；`briefing` 保留行动目标。不要在未展开提示时把所有关键时刻直接告诉玩家。C0 教学保留直接说明。`theme: 'gala'` 使用拍卖会暖色，`industrial` 使用配电站冷色，`clockwork` 使用车站铜褐色，`audit` 使用转存区紫灰色，视觉与声音继续由代码绘制。

## 参考输入

参考解支持 `go: [x,y]`、`wait: 帧数`、`press: interact/lure`、`record: true`、`delay: 帧数 + echo: 下标`。路线验证器将移动转换为键盘可表达的八方向输入，不传送、不绕过碰撞；到达不了目标、超过时限或被发现都会报错。`playWitness` 的可选逐帧观察回调用于检查实际路线中的取物、断电与恢复顺序，不应修改游戏状态。

```sh
npm run check:content
npm test
npm run build
npm run test:browser
```

检查器同时检查重复 ID、未知开关/电源/授权、实体与障碍重叠、前置事实和全区参考解。新增独立机制还需要测试冲突、重录、存档和预演隔离，不能仅凭一条通关路线验收。

最后进行真人首玩：记录是否理解当前目标、是否改过计划、失败能否解释、与前一区有什么不同。自动通过不等于谜题已达到发布质量。
