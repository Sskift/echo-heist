# 关卡与叙事创作

引擎固定 60 Hz，每轮 12 秒，最多三个回声。`src/levels.ts` 定义设施类型；`src/campaign-authoring.ts` 提供房间和行动辅助函数；八章内容在 `src/campaign-content.ts` 与 `src/chapter-*.ts`。

每个任务连接若干行动区。行动区含地图、入场台词、成功结果、所得事实、前置事实和参考路线。成功抵达锚点后才提交进度；后续区重新规划回声。分支使用 `outcomes` 记录供电状态或实际凭据交付位置，`variants` 按已经提交的事实选择下一布局，所有分支保留共同剧情事实。

证据准备的样板在 `src/mission-preparations.ts`。`Mission.preparations` 的第一项是无需证据的原路线；其余项的 `sources` 只引用已经成功归档的前序任务。准备 ID 在本任务起点作为布局事实，选择对应的 `variants`；变体拥有独立关卡 ID 与录像，仍提交原规范阶段 ID。每项写明设施变化与配合代价，不从故事已读状态授予权限。

`Campaign.depart` 在真实出发或恢复既有录像时锁定安排；预演不能锁定或提交。普通重试、清空录像和阶段回退保留准备。仅「重新准备」回到任务起点并清理全部阶段录像和后续结果，历史证据保留。没有准备字段的旧存档沿原路线继续；无法识别的准备撤回到安全起点。验证器从每项准备执行完整提交链并逐段重载，不仅孤立检查变体。

机械门闩复用指定状态的录像意图，`Circuit.mechanical` 只选择黄铜拉杆模型与门闩文案；实际通行仍由门的 `power` 与 `plate` 条件共同决定。每轮门闩复位，重复松闩不会反向扣紧，不能从视觉拉杆位置推断模拟状态。

C3-5 的旁路样板在 `src/grid-preparation.ts`。`Circuit.feed` 也可读取本区确认位；显示层给自动接线柜使用无手动拉杆的模型，标签注明控制开关，状态与连线读取实际馈线供电。取物和撤离继续分别声明 `lootPower`、`exitPower`，旁路不能只在文案里要求归位。复制带渐进提示的关卡时，应同时替换 `hints`、`hint` 与 `briefing`，避免显示旧路线提示。

3D 显示层在 `src/scene3d.ts`，模型在 `src/models3d.ts`。地图仍以原始平面坐标创作，碰撞、视野和录像不读取模型网格。墙体装饰只能进入已有实体范围；标签和危险范围从真实规则生成。画面方向输入经 `screenMovement` 转回世界坐标，作者参考路线仍按世界坐标执行。浏览器路线通过辅助函数按对应组合键输入，另有一条真实屏幕方向输入验证。

`src/scene-finish.ts` 只负责显示：桌面全细节使用 HDR 灯光晕染、输出色调映射与 FXAA，手机和简洁模式直接渲染。复用的表面凹凸使用固定种子，不能影响模拟随机性。墙脚接触阴影只烘焙静态墙体，不包括门、角色或设备状态；门开闭、角色和回声仍读取实际模拟。扩展美术时同时检查桌面、手机、多人场面、重复换房后的资源数量和实际渲染成本。

章节建筑与陈设在 `src/set-dressing.ts`，`setting` 按章节 ID 选择空间用途，`sceneLook` 提供统一墙面、地面、压边与灯色。独立展柜、转运箱和设备箱替换已有实体块，柜面靠近已有交互点，地面标识不增加碰撞。电路拨杆读取 `game.circuits`；扫描和抑制发射器读取 `scanning` / `suppressionActive`，不能从单独的视觉计时器推断开关。新增每区纹理、材质和几何体应设置对应 `ownedTexture`、`ownedMaterial`、`ownedGeometry` 标记，供切换房间时释放；复用的模型和基础网格不设置独占标记。角色用稳定的颜色编号绑定回声，动作按模拟帧而非墙上时间播放，凭据显示读取真实 `tokenOwner`。

跨区凭据样板在 `src/station-transfer.ts`。`credential.id` 定义同一物件，`from` 引用前区规范 ID；`incomingOwners` 与 `incomingAuthorizations` 限定入站状态，`exitOwners` 与 `exitAuthorizations` 限定可提交事实。需要本人接回时声明 `receiveByPlayer`，回声的领取不满足它。后区不能再配置 `source`；参考路线必须使用前区真正成功提交的状态。`Terminal.transfer: 'give'` 表示只收不取的归还槽，允许空手录下交付请求，实际执行仍须持有原票。重试恢复入站快照，回退删除后段凭据记录和本区计划。

`src/museum-return.ts` 复用序章入口、门、开关与遮挡布局，将 C7-6-b 的恢复回执带到 C7-6-f。中间三个行动区不生成或转交该回执；它保留在成功锚点里，最终段以 `from` 接入。`credential.journey` 提供该物件专用的去向说明。`setting: 'museum'` 选择旧馆美术，`lostProperty` 设置共享失物柜地标，`appearance: 'lost-property'` 的只收不取终端必须在柜前一格。铭牌、纸张与交互提示读取实际 HOME 持有状态，不能靠故事阅读状态改变。

`restorationVersion: 1` 标记已处理恢复回执的新存档。仅旧格式中连续成功归档的 C7-6-b 可以补发 ROOT / RESTORED 回执；历史完成列表或结局列表本身不构成取得回执的证据。新格式缺失或损坏的回执必须回到该锚点重做，不能重复迁移。最终归档完成后刷新展示已验证的柜中回执，明确重试仍恢复本区入站快照。

连续房间的样板在 `src/last-light.ts`。首区 `handoff` 要求只有一名回声且终点守住所需开关，成功后把原始录像复制进任务锚点。后段 `continuity.source` 引用首区；离开原房间时，由无真人的原房间模拟按相同帧号播放，`Circuit.feed` 读取实际开关。返回原房间时使用 `home`，留守者参与当前房间的交互与检测。它始终占第一个名额，不能在后段删除、改延迟或重录；本区计划只存另外两格。每区每轮从零同步，不延续上一区的余秒。新增任务若要使用这个机制，仍限一名留守者。

`alternateExit` 让前段准备同时改变实际出口与后续出生点。回退会删掉后续决策、锚点与本区录像；参考验证必须从实际前区胜利取得录像，不能为后段硬造一个永久开启的开关。旧 C3-6 四区存档保留历史通关和后续解锁，只重开改版后的这一场任务。

参考路线只能使用移动、等待、录制、按键、出场延迟和删除回声。`src/witness.ts` 按真实输入执行，不传送玩家或改写世界状态。所有布局与分支组合统一在 `npm run check:content` 校验；不要再复制到章节单元测试和浏览器脚本里。

关键规则：

`src/handoff-preparations.ts` 包含 C4-5、C5-5 的证据准备。`Terminal.appearance` 的 `legacy` / `manual` 只选择外观；供电和签入条件仍声明在 `power`、`plate` 与授权字段里。C5-5 末区使用没有 `from` 的本区 `credential`：必须在 BACK 实际接回，持有并完成 L 授权才能提交。不能把 C4-6 的车票记录复制成新任务的原票。取物、值守、归位和本人接收的要求必须由规则验证，不能仅写在提示里。

`src/dock-preparation.ts` 用同一收货端坐标衔接 C2-1 两区，并为声响回声设置真实收货箱掩体。`src/review-preparations.ts` 使用 REVIEW 的相反状态分别控制进入、签名与回程；`lootPower`、`exitPower` 保证取证和归位顺序，不能只在文案要求恢复。C7 收件口的 Q 归位与 B → CHECK 馈线同样由真实状态检查。`Terminal.appearance: 'review'` 仅选择复核台模型。电源连线读取各门的完整 `Power` 条件，逆向供电不能沿用正向颜色。

- 回声精确播放历史位置，终点持续值守；三槽满时不能静默丢掉录像。
- 电路录像记录指定状态；同帧冲突取消。取物或植入造成的状态变化需要提前向玩家说明。
- 凭据只有一份。交付、接收、授权按实际条件完成，不能复制。留候只在原位置和有效投影中维持。
- 抑制场让回声暂时不能值守或操作，不停止录像进度；离场后继续当前动作，不补发错过的按键。
- 送达需要真人植入。要求独立回执时，指定安保人员必须调查副本并返回登记位置。
- 民用恢复条件必须在 `exitPower` 等真实规则里执行，不能只写在结果台词中。

叙事新段落加入 `src/story.ts`，指定章节、任务、到达或完成时机与页文。关键事实只能在已有证据之后出现。响应早前对话时注明来源场景，省略回答必须有中性文本。更改规则、人物事实或结局范围时同时更新 [叙事编排](story-bible.md)。

验证只保留三层：`npm test` 检查核心机制与存档，`check:content` 检查作者内容，`test:browser` 检查少量完整用户流程。UI 改动还需要实际查看桌面与手机截图；不要为纯文案或装饰增加镜像断言。
