正式主线共 39 个任务、104 个行动区，完成一章后可直接进入下一章。C1 章末回执室可用一条往返回声走上方通道，也可用两条留守回声走下方检修通道。C2 章末最后可用回声开下门或零回声等待上方时序门。C3 章末先完成核心拆离与民用主线恢复，最后一段可使用回声压力门或零回声检修窗口接入备用馈线。C4 章末前三段接通终端、连续交接、取走货单并恢复出口；末段可凭据接力，也可先本人持票进入、录下内侧人工放行，再让下一轮走检修门。C5 章末拆开感知与抑制网络，取件后按顺序保护留守者，最后可让两条回声诱导追踪器，或只留一名同伙、由真人先切断追踪供电再释放它。C1–C5 的替代方案均已分别通过引擎验证。

C6 前三个任务各有两条完整可执行方案。入口会改变后续设施；先通信或先记录会交换两个取证阶段的布局、行动与帮助关系；供电会留下签名终端与监控，或暗处巡逻与开放通道。四个额外分支布局是同一批行动区的替代版本，不额外计入必经体量。两种取证顺序都明确核验 B-17 仍活着，现实中的重逢与故事终局尚未完成。

已制作任务的设计预算合计 587 分钟，**没有真人实测结果**。这不代表当前版本已经有对应时长的有效内容。

## 已实现的系统

| 系统 | 行为与边界 |
| --- | --- |
| 任务与锚点 | 成功才提交；刷新恢复下一阶段；回退移除之后的本轮事实，保留历史任务解锁；回声按行动区保存 |
| 跨阶段选择 | 显示电路两态与下一间后果，真人成功才提交；按前序结果选择后续布局；分支录像隔离，回退删除后续选择；缺失或无效的选择存档停在可核验锚点 |
| 延迟出场 | 0–6 秒、0.25 秒步长；数字输入或加减；编辑暂停；末尾截断可见；支持撤销与重录 |
| 时序门禁 | 多开关同时成立、任一成立、恰好一人或全部离岗；可组合响应窗口和多次开门 |
| 周期扫描 | 公开范围、周期、倒计时；连续暴露 0.3 秒失败；可在只读预演检查 |
| 设备操作 | E 记录明确电源状态或凭据请求；回放检查实体 ID、距离和当下条件 |
| 供电与照明 | 分流器两态可分别服务不同设施；供电影响门和摄像头，照明缩短相关守卫视距但不影响听觉；连线与面板显示实际状态 |
| 取物后果与完成条件 | 取物、撤离可要求特定供电；核心拆离只触发一次已预告的断电，恢复后才可撤离；回声、重录与预演不能代替真人取物 |
| 唯一凭据 | 一个持有者；交付先于接收；同帧竞争取消；授权需要持有凭据并保留持有权 |
| 交接条件与留候 | 终端可要求时段、供电、远端开关、前置签名；标明留候的终端接收请求可等待送件，离开或被抑制取消；地图与面板显示时段、持有者、等候者和条件 |
| 抑制场 | 可固定、受电源控制或按公开周期启动；重叠时任一层开启就失效；投影继续走并保留凭据，恢复后不补放事件；真人不受影响 |
| 投影追踪器 | 只看可见回声，按距离及稳定编号选目标；追向最后可见位置，线索到期返回原路线；声响调查优先；断电清除追踪、调查与警觉；地图和预演公开路径 |
| 只读预演 | 克隆已提交计划，检查 0–12 秒；不含真人、不保存进度；暴露时停在失败处 |

| 玻璃与公开规则 | 玻璃挡身体不遮视线；地图显示守卫编号、调查目标与参考响点；安保面板显示响应规则、视听范围及搜索状态 |

模拟次序：更新开关 → 移动与声响 → 分派调查 → 记录 E 请求 → 结算电源请求 → 按最新抑制状态结算交付、接收、授权 → 更新门禁 → 守卫与扫描感知 → 真人取物及一次性后果 → 更新受影响门禁 → 核对撤离条件与时限。取物后果覆盖这一帧更早的电源请求；影响安保时从下一帧感知。电源对声响的影响从下一模拟帧开始。同帧相反电源请求不改变状态。

## 验证与局限

所有 108 个主线与机制试验行动区、112 个含分支的布局均有真实引擎下通过八方向输入完成的参考解，C1–C5 章末替代解单独回放。原有三关也有实际路线回归。浏览器覆盖真实键盘通关、延迟避扫、回执撤离、玻璃诱导、双声源分配、零回声撤离、电路录像、照明视距、核心拆离与民用恢复、提示分层、存档、重录、预演、空手接收、时段接力、留候与远端授权、连续签名、车站两条末段路线、抑制脉冲与真人接管、追踪器预演、失效时持有凭据、恢复时重新接收、审计员末段两解、移动端布局和试玩导出。

C2 还验证去掉声响后的关键路线会失败，以及第一声确实会改变第二声的响应守卫。空间索引加速墙体碰撞与视野查询，对照原始几何算法验证非网格墙体、边界、玻璃和动态门。

C3 验证每条参考路线去掉电路操作后无法完成、只开门而不停共线监控会暴露，以及真实核心路线按“取物前供电 → 取物断电 → 后续恢复 → 成功”推进。独立单元用例还验证没有实体门时也不能绕过撤离条件，同帧提前恢复会被随后拆离覆盖，重试回到原供电，预演与重录不触发实体后果。

C4 验证窗口首尾帧、同帧交付接收、竞争取消、等候不重复发出请求、离开与抑制取消、存档重建与预演隔离。参考输入还检查空手录制失败而回放成功、远端无人时授权失败、漏掉前置签名无法完成，以及货单取出后监控启动、恢复 P 才能撤离。两种章末路线分别让真人接到凭据、或让回声保留凭据并操作内侧电源，交接记录不同。

C5 验证周期首尾帧、相位和重叠，追踪器不识别真人、只记最后可见位置、视线遮挡与玻璃差异、目标排序、声音覆盖和断电清除。实际路线验证缺少延迟或诱饵会失败，抑制中凭据不会丢，留候取消后必须重新请求，三回声分时控制能完成，以及取件后先恢复同伙再关追踪会失败。章末两种方案分别保留追踪供电并诱导调查、或关闭追踪供电，全程真实输入。

C6 验证三任务的两条完整分支、逐锚点刷新、回退重选、缺失选择修复、错误布局拒绝提交、预演与重录隔离。前半章两种入口分别需要凭据接力与双人留守；两种取证顺序改变两个后续布局；两种供电结果分别支持单回声签名路线与零回声暗处路线。取证诱饵有反例验证，去掉声响无法完成回程。时长记录按共同阶段编号归档，另存实际分支与选择事件，避免把两个替代布局计作两个必经阶段。

自动参考解证明可完成，不证明首次玩家理解、谜题质量或游玩时长。真人测试尚未开展。时长审查命令会检查完整内容、全体开测名单、导出哈希和人工复核；缺 C6 后半章、C7 或缺真人数据时明确失败。[试玩协议](playtesting.md) 说明统计口径和外部核对要求。

M0 的四种机制已有可玩样例，仍需玩家判断直观性与趣味性。前六章已经可玩；作者工具仍是数据定义与命令行验证，没有拖放编辑器。完整八章、剧情结局、十二份特别契约、组合任务、回放分享与玩家编辑器未完成。完整目标逐项见 [目标审查](goal-audit.md)。
